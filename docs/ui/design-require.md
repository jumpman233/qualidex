# Qualidex 前端页面设计要求

请基于 electron-vite + React + TypeScript 实现一个单页工作台界面。

产品是一个 Windows 本地人员资料归档与资质查询工具，用户主要是非技术人员。

页面风格参考 Notion / 飞书工作台 + ChatGPT 输入框，不要做成传统复杂后台。

## 页面结构

整体为单页 AppShell：

1. 顶部栏
   - 左侧显示 Qualidex
   - 副标题：人员资料归档与资质查询工具
   - 右侧显示 当前资料库、设置、帮助

2. 智能操作区 CommandBar
   - 一个大输入框
   - placeholder 示例：
     - 找成都 3 个大专以上、有二建证、资料齐全的人
     - 新增一批工程类成都资料
     - 处理待确认资料
   - 快捷按钮：
     - 查询人员
     - 新增资料
     - 查看待确认
     - 导出记录

3. 状态概览区 OverviewCards
   - 已整理人员
   - 待确认资料
   - 最近新增
   - 导出记录

4. 主工作区 MainWorkspace
   根据 workspaceMode 切换：
   - home
   - search
   - import
   - review
   - export

## 交互要求

### 查询模式 search

用户输入自然语言后，先展示“系统理解的查询条件”卡片，不直接查结果。

条件卡片包含：
- 类别
- 地区
- 人数
- 学历
- 证书
- 资料完整度
- 是否包含待确认

按钮：
- 确认查询
- 修改条件

确认后展示人员结果卡片。

人员卡片字段：
- 勾选框
- 姓名_唯一标识
- 类别 / 地区 / 学历 / 证书
- 资料完整度
- 匹配原因
- 状态标签
- 操作按钮：查看资料、打开文件夹、加入导出

### 新增资料模式 import

展示新增资料卡片：
- 资料类别下拉框：工程 / 环境 / 消防员 / 自动识别
- 地区输入框或下拉框
- 选择文件夹按钮
- 开始整理按钮

整理过程中展示进度：
- 扫描文件
- 识别文字
- 整理人员
- 生成待确认

完成后展示摘要：
- 新增人员
- 更新已有人员
- 重复文件
- 待确认资料

按钮：
- 处理待确认
- 查看本次新增人员
- 生成归档

### 待确认模式 review

第一版采用卡片式确认，不做复杂表格。

每张卡片包含：
- 问题类型
- 文件名
- 系统猜测结果
- 原因
- 查看文件按钮
- 查看识别文字按钮
- 可编辑字段：
  - 类别
  - 地区
  - 人员
  - 资料类型
- 操作按钮：
  - 确认
  - 跳过
  - 标记为无法识别

如果待确认数量较多，顶部预留“展开列表”按钮，但第一版可不实现复杂列表。

### 导出模式 export

展示导出预览：
- 本次导出人员列表
- 导出内容选择：
  - 人员清单 Excel
  - 人员资料文件夹
  - 是否包含多人员共用资料
- 导出位置
- 风险提示

按钮：
- 开始导出
- 修改选择
- 取消

## 视觉风格

- 背景使用浅灰
- 主内容使用白色圆角卡片
- 卡片之间留足间距
- 字体层级清晰
- 少用强颜色
- 状态标签使用柔和颜色
- 危险操作使用红色
- 主按钮醒目但不要刺眼

## 技术要求

- 使用 React + TypeScript
- 组件化拆分
- 使用 mock data 先实现静态交互
- 暂不接真实 Electron API
- 不要实现复杂状态管理库，第一版用 useState 即可
- 后续 Electron 主进程能力通过 service 层接入
