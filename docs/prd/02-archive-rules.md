## 6. 归档目录规则

### 6.1 标准归档结构

归档输出目录结构：

归档输出/  
  主类别/  
    地区/  
      人员姓名_唯一标识/  
        01_身份证/  
        02_学历/  
        03_执业执照/  
        04_其他资料/

示例：

归档输出/  
  工程/  
    成都/  
      张三_1234/  
        01_身份证/  
        02_学历/  
        03_执业执照/  
        04_其他资料/  
      李四_5678/  
        01_身份证/  
        03_执业执照/  
    未划分区域/  
      王五_9012/  
  环境/  
    重庆/  
      赵六_3344/  
  消防员/  
    绵阳/  
      钱七_5566/

- MVP 阶段一个人员只归入一个主类别目录  
- 多类别查询仅作为筛选条件，不表示人员同时出现在多个目录  
- 多类别复制归档作为后续增强功能设计

### 6.2 主类别规则

MVP 阶段主类别：

工程  
环境  
消防员  
未识别类别

来源：

1. 用户导入手动指定  
2. 原始文件夹路径  
3. 相对路径和层级  
4. 原始文件名  
5. OCR 文本  
6. AI 抽取结果  
7. 人工确认

数据库字段：

primary_category  
primary_category_source  
primary_category_confidence

后续支持多类别人员扩展：

people.primary_category  # 归档主目录  
person_categories         # 查询和业务标签

### 6.3 查询类别规则

多选查询：

找工程和消防员里成都有二建证的人

解析为：

{
  "categories": ["工程", "消防员"]
}

默认语义：类别属于 工程 或 消防员

MVP 查询 SQL：

WHERE primary_category IN ('工程', '消防员')

多类别逻辑后续：

WHERE EXISTS (
  SELECT 1
  FROM person_categories pc
  WHERE pc.person_id = people.id
    AND pc.category IN ('工程', '消防员')
)

同时属于多类别提示：

当前版本按任一类别匹配。如需同时属于多个类别，需要后续启用多类别人员模型。

### 6.4 地区规则

第二层目录：

已识别地区  
未划分区域

来源：

1. 用户导入手动指定  
2. 原始文件夹路径  
3. 相对路径和层级  
4. 原始文件名  
5. 已有人员台账  
6. 证书文本  
7. 业务规则  
8. 人工确认

数据库字段：

region  
region_source  
region_confidence

### 6.5 人员文件夹规则

命名：

人员姓名_唯一标识

优先：

姓名_身份证后四位，例如 张三_1234

缺失则使用系统编号，例如 张三_P000123，进入待确认

### 6.6 资料类型规则

目录下资料类型：

01_身份证  
02_学历  
03_执业执照  
04_其他资料  
99_待确认

无法判断类型进入 99_待确认

### 6.7 多人员资料规则

- PDF 或图片含多人员资料，不归单人目录  
- 放入：

归档输出/  
  主类别/  
    地区/  
      _多人员资料/  
        多人员资料_文件名或编号/  
          原始文件.pdf  
          关联人员清单.xlsx

- 数据库建立文件与多人员关联  
- MVP 不自动拆分，多人员文件仅识别、关联、待确认、提醒导出

### 6.8 二次归并规则

- 同文件夹所有文件汇总  
- AI/规则判断归属、冲突、多证书  
- 冲突或多人员文件夹进入人工校验  
- 支持导入完成 CTA、路径解析、证书来源可信度、类别动态提供

### 6.9 人工校验流程

- 待确认项面板显示文件、人员组、来源文件夹、OCR 摘要、AI 判断结果  
- 操作：确认归属、指派、创建新人员组、标记无法确认  
- 可直接打开来源文件夹和人员相关文件
