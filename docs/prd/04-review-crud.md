# Qualidex PRD 拆分文档

> 来源：Qualidex PRD V1.4  
> 产品形态：Windows 本地桌面工具  
> 技术栈：Electron + electron-vite + React + TypeScript + SQLite + sqlite-vec + 本地 OCR + 云端文本 AI API

## 11. 人员归并功能

### 10.1 归并规则

人员归并优先级：

```text
1. [P0] 姓名 + 完整身份证号一致：高置信度同一人
2. [P0] 完整身份证号一致但姓名不一致：进入待确认，禁止自动覆盖姓名
3. [P0] 姓名一致但完整身份证号不同：进入待确认，禁止自动合并
4. [P1] 姓名 + 地区 + 主类别一致：疑似同一人，需要结合文件夹级二次归并和人工确认
5. [P1] 姓名一致但地区不同：进入待确认
6. [P1] 姓名一致但主类别不同：进入待确认
7. [P0] 无姓名或无完整身份证号：进入待确认
```

身份证号使用规则：

- [P0] 数据库使用 `id_card_number` 保存完整身份证号明文，仅限本地 SQLite。
- [P0] 页面可直接展示完整身份证号；`masked_display` 只用于云端 AI 脱敏输入、导出默认脱敏值和隐私场景展示。
- [P0] `id_card_hash` 用于查重和归并辅助。
- [P1] `id_card_number_encrypted` 可作为后续加密存储字段预留。
- [P0] 不允许一个人员同时关联多个不同身份证号；冲突时进入待确认。

### 10.2 同名冲突

当出现同名人员时，页面应提示：

```text
检测到同名人员：
- 张三_1234****5678，工程 / 成都
- 张三_5678****1234，工程 / 重庆
- 张三_P000091，未划分区域

请选择当前文件归属人员，或新建人员。
```

### 10.3 人员合并与拆分

需要支持：

```text
合并人员
拆分人员
更换文件关联人员
```

所有操作写入操作日志。

### 10.4 文件夹级二次归并

[P1] 同一文件夹内的文件应进行二次归并，用于修正单文件 OCR / AI 判断不足的问题。

二次归并输入：

- 文件夹路径和相对路径。
- 文件夹内所有文件名。
- 每个文件的 OCR 文本摘要。
- 每个文件的 AI 结构化结果。
- 完整身份证号、姓名、证书、地区、主类别候选。

处理规则：

- 同一文件夹内文件明显属于同一完整身份证号时，可归并为同一人员。
- 同一文件夹内出现多个完整身份证号或多个人名时，生成待确认项。
- 同一文件夹内存在多证书时，应关联到对应人员的多条 `licenses` 记录。
- 文件夹级判断只能作为归并建议，冲突必须进入待确认。

## 12. 待确认功能

### 11.1 待确认类型

待确认项包括：

```text
person_unknown
person_merge_conflict
primary_category_unknown
primary_category_conflict
region_unknown
document_type_unknown
license_uncertain
license_recognition_uncertain
education_uncertain
multi_person_file
ocr_failed
ai_extract_failed
path_ocr_conflict
path_category_conflict
path_region_conflict
path_person_conflict
```

### 11.2 待确认页面能力

页面需要支持：

1. 查看原始文件。
2. 打开原始文件所在目录。
3. 查看 OCR 文本。
4. 查看 AI 抽取结果。
5. 修改主类别。
6. 修改地区。
7. 修改人员。
8. 修改资料类型。
9. 修改证书名称。
10. 修改证书是否认可。
11. 手动标记证书官方 / 非官方标签。
12. 清空证书官方 / 非官方标签，恢复为未判断。
13. 标记为多人员资料。
14. 标记为忽略。
15. 确认归档路径。
16. 查看文件夹路径和相对路径解析结果。
17. 查看多证书归属建议。
18. 查看完整身份证号，并保留脱敏值用于导出默认值和 AI 脱敏输入。

### 11.3 批量确认

MVP 可支持简单批量操作：

```text
批量设置主类别
批量设置地区
批量标记为其他资料
批量忽略
```

## 16. 修改功能

### 15.1 可修改对象

支持修改：

```text
人员信息
- 姓名
- 完整身份证号
- 身份证号 AI 脱敏值 / 导出默认脱敏值
- 主类别
- 地区
- 学历
- 人员合并 / 拆分

文件信息
- 资料类型
- 关联人员
- 是否多人员资料
- 是否忽略
- OCR 文本修正

证书信息
- 原始证书名
- 归一化证书名
- 是否认可
- 官方 / 非官方标签，默认未判断
- 有效期
- 证书类别
- 颁发机构
- 颁发机构可信度预留字段
```

完整身份证号修改规则：

- [P0] 默认页面可展示完整身份证号。
- [P1] 修改完整身份证号需要明确用户操作，并写入 `audit_logs`。
- [P1] 修改后重新计算 `id_card_hash` 和 `masked_display`。
- [P0] 如果新身份证号与已有人员冲突，必须进入待确认，不自动合并。
- [P0] 云端 AI 不参与完整身份证号确认。

证书官方 / 非官方标签规则：

- 可选值为 `官方`、`非官方`、`未判断`。
- 数据库存储建议为 `official`、`unofficial`、`null`。
- 默认值为 `null`，不得由 AI 自动设定。
- 只能由用户在待确认页、人员详情页或证书编辑页手动设置。
- 每次修改都需要写入 `audit_logs`。

一人多证书规则：

- [P0] 一个人可以关联多条证书记录。
- [P0] 待确认页必须展示该人员关联的所有证书摘要。
- [P1] 修改、导出、批量确认和冲突提示必须支持多证书。
- [P1] 证书归属不确定时，应允许把证书改派给已有人员或新建人员。
- [P1] 证书有效期、官方 / 非官方标签、颁发机构、可信度预留字段应完整展示。

多人员文件规则：

- [P0] PDF / 图片包含多人员信息时，文件标记为 `is_multi_person_file = 1`。
- [P0] 数据库建立文件与所有涉及人员的关联。
- [P0] 归档时文件只复制到 `_多人员资料`，不自动复制到每个人目录。
- [P1] 人员详情和导出中提示该人员引用了多人员资料。
- [P1] 待确认页允许查看原始文件、文件夹路径、OCR 文本和 AI 抽取结果。

导入完成 CTA：

- [P1] 导入 / 处理完成后，如果存在待确认项，页面主操作指向“待确认资料”。
- [P1] 如果没有待确认项，页面主操作指向“归档预览”。
- [P1] 归档预览后再引导查询 / 导出。

### 15.2 修改流程

```text
用户修改结构化信息
  ↓
写入数据库
  ↓
写入 audit_logs
  ↓
相关人员 / 文件标记 archive_dirty
  ↓
用户查看归档变更预览
  ↓
确认后重新生成归档
```

### 15.3 归档变更预览

示例：

```text
即将执行以下变更：
- 张三_1234 从 工程/未划分区域 移动到 工程/成都
- 文件 A 从 99_待确认 移动到 03_执业执照
- 多人员PDF_001 新增关联人员：李四_5678
```

这里的“移动”只作用于归档输出目录，不作用于原始资料目录。

## 17. 删除功能

### 16.1 删除归档结果

安全级别最高。

作用：

```text
只删除归档输出目录中的复制文件
不删除原始文件
不删除数据库记录
```

用于重新生成归档、清理错误输出。

### 16.2 从系统中移除文件

文件软删除。

```text
文件不再参与查询
文件不再参与归档
原始文件不删除
可从回收站恢复
```

数据库字段：

```text
archive_status = deleted
deleted_at
deleted_reason
```

### 16.3 删除人员

人员软删除。

删除前提示：

```text
该人员关联：
- 身份证 1 个
- 学历 1 个
- 证书 3 个
- 多人员 PDF 2 个

删除后：
- 不再出现在查询结果
- 不再参与导出
- 原始文件不会删除
- 可在回收站恢复
```

### 16.4 回收站

回收站支持：

```text
查看已删除人员
查看已删除文件
恢复人员
恢复文件
彻底清理归档输出副本
```

MVP 不支持物理删除原始资料。
